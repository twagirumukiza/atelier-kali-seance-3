Partie 3 — Installer le laboratoire

OBJECTIF

Disposer de deux machines virtuelles qui communiquent sur un réseau privé, avec une application cible qui répond sur le port 3000. Chaque étape se termine par une vérification : ne passez pas à la suivante tant qu'elle échoue.

3.1 Prérequis matériels et logiciels

ÉlémentRecommandation
Mémoire de la machine hôte8 Go minimum, 16 Go confortable (Kali 4 Go + Ubuntu 2 Go + système hôte)
Espace disque libre60 Go environ (30 + 20 + marge)
Virtualisation matérielleActivée dans le BIOS/UEFI (Intel VT-x ou AMD-V)
LogicielsVirtualBox (version récente), image officielle Kali pour VirtualBox, ISO Ubuntu Server LTS
PIÈGE

Si VirtualBox refuse de démarrer une VM 64 bits, la virtualisation est désactivée dans le BIOS ou un autre hyperviseur l'occupe (Hyper-V sous Windows).

3.2 Choisir le mode réseau

VirtualBox propose plusieurs modes. Le choix détermine ce que vos VM peuvent atteindre.

ModeVM ↔ VMVM → InternetHôte ↔ VMUsage dans l'atelier
NATNonOuiNon (sans redirection)Temporaire : mises à jour
Host-only (réseau hôte uniquement)OuiNonOuiRecommandé pour le labo
Réseau interneOuiNonNonIsolement maximal
Pont (bridge)OuiOuiOuiÀ éviter : expose la cible au réseau réel
RÈGLE R8 Isoler le laboratoire

Une cible volontairement vulnérable ne doit jamais être exposée à un réseau réel. On utilise le mode Host-only, sans redirection de port, et on désactive la carte NAT une fois les installations terminées.

Configuration conseillée : chaque VM a deux cartes. La carte 1 en NAT sert aux installations ; la carte 2 en Host-only porte le trafic d'atelier. Une fois les logiciels installés, on désactive la carte NAT.

ÉTAPE 3.2.1Créer le réseau Host-only

  1. VirtualBox → Outils (ou Fichier) → Gestionnaire de réseau hôte → créer un réseau (souvent nommé vboxnet0). Notez son adresse : en général 192.168.56.1/24.
  2. Pour chaque VM (arrêtée) : Configuration → Réseau → Adaptateur 1 : NAT ; Adaptateur 2 : Réseau privé hôte (Host-only) → sélectionner vboxnet0.
  3. Ne créez aucune redirection de port.
ATTENDU Vérification

L'adresse du réseau hôte correspond à la plage choisie ; les deux VM utilisent le même réseau Host-only.

3.3 Installer la machine Kali Linux

ÉTAPE 3.3.1Importer l'image officielle

  1. Téléchargez l'image officielle Kali pour VirtualBox sur le site de Kali.
  2. Vérifiez l'empreinte de contrôle fournie.
  3. Importez-la : Fichier → Importer un appareil virtuel.
  4. Réglez 2 vCPU et 4 Go de RAM.
  5. Démarrez. Les identifiants par défaut sont indiqués dans la documentation officielle de l'image ; changez le mot de passe dès la première connexion.
RÈGLE R10 Vérifier l'intégrité de ce que l'on télécharge

On télécharge uniquement depuis le site officiel et on compare l'empreinte (hash) publiée avec celle du fichier obtenu. Un fichier modifié peut contenir un code malveillant.

kali@kali: ~
kali@kali:~$ passwd
Changing password for kali.
Current password:
New password:
Retype new password:
passwd: password updated successfully
RÈGLE R13 Changer les secrets par défaut

Un mot de passe par défaut est connu de tous. Il se change dès la première connexion — y compris sur une machine de laboratoire, pour prendre le bon réflexe.

ÉTAPE 3.3.2Mettre à jour et installer les outils (carte NAT active)

kali@kali: ~
kali@kali:~$ sudo apt update
kali@kali:~$ sudo apt full-upgrade -y
kali@kali:~$ sudo apt install -y nmap nikto gobuster wireshark tshark exiftool curl
CommandeRôle
sudoExécute la commande avec les droits administrateur
apt updateTélécharge la liste des paquets disponibles (n'installe rien)
apt full-upgrade -yMet à jour tous les paquets ; -y répond « oui » aux confirmations
apt install -y …Installe les outils listés
ATTENDU

La dernière ligne n'affiche pas d'erreur E:. Selon la version, certains paquets sont déjà présents ; le nom d'un paquet peut varier.

ÉTAPE 3.3.3Autoriser la capture sans droits excessifs

Wireshark capture via un composant privilégié (dumpcap). Pendant l'installation, répondez « Oui » à la question sur l'autorisation des utilisateurs non-root, puis ajoutez votre utilisateur au groupe wireshark :

kali@kali: ~
kali@kali:~$ sudo usermod -aG wireshark kali
# puis : déconnexion / reconnexion pour que le groupe soit pris en compte
kali@kali:~$ id | grep wireshark
uid=1000(kali) gid=1000(kali) groups=1000(kali),...,wireshark
RÈGLE R7 Moindre privilège

On accorde à un compte ou à un programme uniquement les droits nécessaires à sa tâche. Ici : autoriser la capture via le groupe wireshark plutôt que lancer toute l'interface graphique en administrateur.

ÉTAPE 3.3.4Vérifier les installations

kali@kali: ~
kali@kali:~$ nmap --version
kali@kali:~$ nikto -Version
kali@kali:~$ gobuster version
kali@kali:~$ exiftool -ver
kali@kali:~$ tshark --version
ATTENDU

Chaque commande affiche un numéro de version. Une erreur command not found signale un paquet manquant.

3.4 Préparer la cible Ubuntu Server

Installez Ubuntu Server LTS en suivant l'assistant : langue, clavier, stockage guidé, nom d'hôte cible, utilisateur. Activez le serveur OpenSSH si l'assistant le propose (le port 22 apparaîtra dans Nmap).

ÉTAPE 3.4.1Mettre à jour et lire la configuration réseau

ubuntu@cible: ~
ubuntu@cible:~$ sudo apt update
ubuntu@cible:~$ sudo apt upgrade -y
ubuntu@cible:~$ sudo apt install -y curl
ubuntu@cible:~$ ip -br addr
lo               UNKNOWN   127.0.0.1/8
enp0s3           UP        10.0.2.15/24
enp0s8           UP        192.168.56.20/24
LigneLecture
loBouclage
enp0s3Carte NAT (adresse 10.0.2.15 attribuée par VirtualBox)
enp0s8Carte Host-only. Si elle n'a pas d'adresse IPv4, il faut la configurer
À RETENIR

Les noms d'interface (enp0s3, enp0s8, eth0…) varient selon la machine. Repérez les vôtres avec ip -br addr.

ÉTAPE 3.4.2Fixer l'adresse de la carte Host-only (Netplan)

Ubuntu Server utilise Netplan. Listez le fichier de configuration puis éditez-le avec sudo nano. Les espaces d'indentation sont obligatoires (YAML) ; pas de tabulations.

ubuntu@cible: ~
ubuntu@cible:~$ ls /etc/netplan/
ubuntu@cible:~$ sudo nano /etc/netplan/50-cloud-init.yaml
/etc/netplan/50-cloud-init.yaml (le nom du fichier peut varier)
network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: true
    enp0s8:
      dhcp4: false
      addresses:
        - 192.168.56.20/24
ubuntu@cible: ~
ubuntu@cible:~$ sudo netplan apply
ubuntu@cible:~$ ip -br addr show enp0s8
enp0s8           UP        192.168.56.20/24
ATTENDU

enp0s8 UP 192.168.56.20/24. Si Netplan refuse la configuration, sudo netplan try indique la ligne fautive.

ÉTAPE 3.4.3Installer Docker et lancer Juice Shop

Suivez la documentation officielle de Docker pour Ubuntu (lien en partie 8). Puis :

ubuntu@cible: ~
ubuntu@cible:~$ sudo docker run -d --name juice-shop --restart unless-stopped \
      -p 192.168.56.20:3000:3000 bkimminich/juice-shop
ubuntu@cible:~$ sudo docker ps
CONTAINER ID  IMAGE                   STATUS        PORTS                        NAMES
a1b2c3d4e5f6  bkimminich/juice-shop   Up 2 minutes  192.168.56.20:3000->3000/tcp juice-shop
ÉlémentRôle
docker runCrée et démarre un conteneur
-dArrière-plan (detached)
--name juice-shopNom du conteneur
--restart unless-stoppedRedémarre le conteneur après un redémarrage de la machine, sauf arrêt volontaire
-p 192.168.56.20:3000:3000Publie le port 3000 du conteneur sur le port 3000 de l'adresse privée uniquement
bkimminich/juice-shopImage de l'application OWASP Juice Shop
À RETENIR Pourquoi préciser l'adresse dans -p ?

Sans elle (-p 3000:3000), Docker publie le port sur toutes les interfaces, y compris la carte NAT. En liant l'adresse privée, on garde l'application dans le laboratoire.

ATTENDU

Une ligne juice-shop, Up …, avec 192.168.56.20:3000->3000/tcp. Au premier lancement, l'image est téléchargée depuis Internet : la carte NAT doit encore être active.

3.5 Configurer l'adresse de Kali

Sur Kali, repérez la carte Host-only avec ip -br addr, puis fixez son adresse avec NetworkManager :

kali@kali: ~
kali@kali:~$ nmcli connection show
kali@kali:~$ sudo nmcli connection modify "Wired connection 2" \
      ipv4.method manual ipv4.addresses 192.168.56.10/24
kali@kali:~$ sudo nmcli connection up "Wired connection 2"
kali@kali:~$ ip -br addr
PIÈGE

Le nom entre guillemets dépend de votre machine : reprenez celui de la liste affichée par nmcli connection show. L'adresse 192.168.56.10 est un exemple.

3.6 Vérifier la communication, couche par couche

On teste dans l'ordre des couches : lien → réseau → transport → application. Un test qui échoue indique la couche en cause.

kali@kali: ~
kali@kali:~$ ping -c 3 192.168.56.20
PING 192.168.56.20 (192.168.56.20) 56(84) bytes of data.
64 bytes from 192.168.56.20: icmp_seq=1 ttl=64 time=0.412 ms
64 bytes from 192.168.56.20: icmp_seq=2 ttl=64 time=0.398 ms
64 bytes from 192.168.56.20: icmp_seq=3 ttl=64 time=0.401 ms
3 packets transmitted, 3 received, 0% packet loss
kali@kali:~$ nc -zv 192.168.56.20 3000
192.168.56.20: inverse host lookup failed: Unknown host
(UNKNOWN) [192.168.56.20] 3000 (?) open
kali@kali:~$ curl -I http://192.168.56.20:3000/
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
TestCoucheAttenduSi échec
ping -c 3Réseau (ICMP)3 packets transmitted, 3 receivedVérifier adresses, même réseau Host-only, VM allumées. Le pare-feu peut aussi filtrer l'ICMP
nc -zv IP 3000 (teste le port sans envoyer de données)Transport (TCP)succeeded ou openConteneur arrêté, mauvaise adresse de publication
curl -IApplication (HTTP)HTTP/1.1 200 OK et des en-têtesApplication non démarrée ou erreur du service
À RETENIR

Si le ping échoue mais que curl fonctionne, le service est joignable malgré un filtrage ICMP : c'est un bon exemple de différence entre « la machine répond au ping » et « le service est accessible ».

Ouvrir l'application : dans le navigateur de Kali, saisissez http://192.168.56.20:3000. La page de la boutique Juice Shop doit s'afficher.

3.7 Isoler le laboratoire et prendre un instantané

  1. Arrêtez les VM.
  2. Dans la configuration de chaque VM, désactivez l'adaptateur 1 (NAT) (décochez « Activer l'interface réseau »).
  3. Redémarrez : seule la carte Host-only reste.
  4. Prenez un instantané (Machine → Prendre un instantané) nommé labo-propre. Il permet de revenir à un état sain après une manipulation.
RÈGLE R9 Garder un état sain de référence

Avant toute manipulation à risque, on prend un instantané. On peut ainsi revenir à un état connu et reproduire un test dans les mêmes conditions.

kali@kali: ~
kali@kali:~$ ping -c 2 8.8.8.8
ping: connect: Network is unreachable
kali@kali:~$ ping -c 2 192.168.56.20
2 packets transmitted, 2 received, 0% packet loss
ATTENDU Vérification

ping -c 2 8.8.8.8 doit échouer (aucune route vers Internet) ; ping -c 2 192.168.56.20 doit réussir.

3.8 Diagnostic des problèmes courants

Diagnostiquer, c'est raisonner : un message d'erreur indique une couche. « refused » signifie que la machine répond mais qu'aucun service n'écoute ; « timed out » signifie que rien ne répond (machine injoignable ou paquets filtrés).

SymptômeCause probableVérification
Network is unreachableAucune adresse sur la carte Host-onlyip -br addr
Ping sans réponseVM éteinte, mauvais réseau VirtualBox, adresses dans des plages différentesMême vboxnet, même /24 ; ip route
Connection refused sur le port 3000Conteneur arrêté ou publié sur une autre adressesudo docker ps, sudo docker logs juice-shop
Connection timed outPare-feu ou mauvaise routesudo ufw status sur la cible, ip route
docker: command not foundDocker non installéSuivre la documentation Docker
Netplan refuse la configurationErreur d'indentation YAMLsudo netplan try indique la ligne fautive
