Partie 4 — Pratiquer : Nmap, Nikto, Gobuster

OBJECTIF

Pour chaque outil : principe → commande décomposée → résultat commenté → ce que l'on conclut → ce que l'on ne conclut pas.

ÉTAPE 4.0Préparer l'arborescence de travail

kali@kali: ~
kali@kali:~$ mkdir -p ~/atelier-kali-1/{nmap,nikto,gobuster,wireshark,metadata,rapport}
kali@kali:~$ ls ~/atelier-kali-1
gobuster  metadata  nikto  nmap  rapport  wireshark

mkdir -p crée les dossiers (et les parents si besoin) ; les accolades {a,b,c} génèrent un dossier par nom. Attendu : six dossiers listés.

RÈGLE R12 Traçabilité

On conserve les commandes exactes, leurs sorties et la date : un résultat qu'on ne peut pas reproduire ni justifier n'a pas de valeur de preuve. Chaque outil enregistre donc ses résultats dans un fichier du dossier de travail.

4.1 Nmap — identifier les ports et les services

DÉFINITION Nmap

Outil de reconnaissance qui envoie des paquets vers une cible et déduit l'état des ports d'après les réponses. Il observe, il n'exploite pas.

ÉTAPE 4.1.1Découvrir les hôtes du réseau (facultatif)

kali@kali: ~
kali@kali:~$ nmap -sn 192.168.56.0/24
Starting Nmap 7.9x ( https://nmap.org ) at 2026-10-21 10:12 CEST
Nmap scan report for 192.168.56.1
Host is up (0.00021s latency).
Nmap scan report for 192.168.56.10
Host is up (0.00008s latency).
Nmap scan report for 192.168.56.20
Host is up (0.00045s latency).
Nmap done: 256 IP addresses (3 hosts up) scanned in 2.54 seconds

-sn = découverte d'hôtes uniquement, sans scan de ports. La sortie liste les adresses qui répondent (Kali, la cible, probablement l'interface de la machine hôte et le serveur DHCP de VirtualBox).

RAPPEL R1 Ne lancez cette commande que sur le réseau Host-only du labo

ÉTAPE 4.1.2Scanner la cible de façon limitée

kali@kali: ~
kali@kali:~$ nmap -sV -T3 -p 22,80,3000 192.168.56.20
ParamètreSignification
nmapLe programme
-sVDétection de version : Nmap interroge le service pour identifier le logiciel
-T3Gabarit de temporisation « normal » (de -T0 très lent à -T5 très agressif)
-p 22,80,3000Limite le scan à ces trois ports TCP
192.168.56.20Cible
À RETENIR

Sans droits administrateur, Nmap utilise un scan par connexion complète (TCP connect). Avec sudo, il utilise par défaut un scan SYN, plus discret, qui n'achève pas la connexion. Les deux conviennent à l'atelier.

RÈGLE R11 Proportionnalité

On limite un scan à ce qui est nécessaire (ports ciblés, cadence modérée -T3). Un scan agressif charge le service, remplit les journaux et peut perturber un système en production.

ÉTAPE 4.1.3Lire le résultat (illustratif)

résultat Nmap (illustratif — votre sortie peut différer)
Starting Nmap 7.9x ( https://nmap.org ) at 2026-10-21 10:15 CEST

LigneLecture
Nmap scan report for …Cible analysée
Host is up (0.00045s latency)L'hôte a répondu ; le délai est très court, ce qui est normal entre deux VM
22/tcp open sshUn service accepte les connexions sur le port 22 et se présente comme SSH
80/tcp closed httpLa machine répond mais aucun service n'écoute sur ce port. Le nom http vient de la table des ports usuels, pas d'une détection
3000/tcp open ppp?Un service écoute. Le nom ppp provient de la table associant le numéro de port ; le point d'interrogation signale une identification incertaine

Les six états d'un port

ÉtatSignificationCe que Nmap a observé
openUn service accepte les connexionsRéponse SYN/ACK
closedAccessible mais aucun service n'écouteRéponse RST
filteredImpossible de savoir : un filtre bloquePas de réponse ou erreur ICMP
unfilteredAccessible, ouvert/fermé indéterminéRéponse à un scan ACK
open|filteredOuvert ou filtré (indécidable)—
closed|filteredFermé ou filtré (indécidable)—

ÉTAPE 4.1.4Voir Nmap « de l'intérieur » avec Wireshark (démonstration)

Lancez une capture Wireshark sur l'interface Host-only, relancez le scan, puis appliquez ce filtre d'affichage :

filtre d'affichage Wireshark
ip.addr == 192.168.56.20 && tcp.port == 3000

Pour un port ouvert, vous devriez observer une séquence SYN → SYN, ACK → ACK (scan par connexion) ou RST (scan SYN). Pour le port 80 fermé, la cible répond RST, ACK immédiatement. Vous voyez ainsi concrètement d'où viennent les mots « open » et « closed ».

ÉTAPE 4.1.5Enregistrer et relire

kali@kali: ~
kali@kali:~$ nmap -sV -T3 -p 22,80,3000 -oN ~/atelier-kali-1/nmap/scan.txt 192.168.56.20
kali@kali:~$ cat ~/atelier-kali-1/nmap/scan.txt
OptionFormat
-oN fichierTexte lisible (usage dans le rapport)
-oX fichierXML (pour traitement par programme)
-oG fichierFormat « grepable » (ancien)
-oA baseLes trois formats à la fois

Options utiles

  • -p- : scanne les 65535 ports TCP (plus long ; acceptable en labo).
  • -Pn : ne teste pas si l'hôte répond au ping avant de scanner. Utile si le ping est filtré (Host seems down).
  • -v : plus de détails pendant le scan.

Conclure

ÉlémentFormulation correcte
Observation« Les ports 22/tcp et 3000/tcp sont ouverts ; le port 80/tcp est fermé »
Preuvescan.txt, avec la commande exacte
Interprétation« Un accès SSH et un service sur le port 3000 sont exposés dans le réseau de labo »
Ne pas conclure« Le serveur est vulnérable » : une version n'est pas une faille tant qu'on n'a pas vérifié son applicabilité

4.2 Nikto — vérifier le serveur web

DÉFINITION Nikto

Scanner web qui envoie un grand nombre de requêtes HTTP prédéfinies pour détecter des fichiers connus, des versions, des configurations faibles et des en-têtes de sécurité absents. C'est un scanner bruyant : il laisse de nombreuses traces dans les journaux du serveur.

ÉTAPE 4.2.1Lancer Nikto

kali@kali: ~
kali@kali:~$ nikto -host http://192.168.56.20:3000 -output ~/atelier-kali-1/nikto/nikto.txt
ParamètreSignification
-host URLCible (adresse, port, schéma)
-output fichierEnregistre le rapport
-Format txt (facultatif)Choisit le format du fichier (txt, htm, csv, xml…)
-Tuning (facultatif)Limite les familles de tests

ÉTAPE 4.2.2Lire le résultat (illustratif)

résultat Nikto (illustratif — votre résultat peut différer)
- Nikto v2.x
+ Target IP:          192.168.56.20
+ Target Port:        3000
+ Server: No banner retrieved
+ /: The anti-clickjacking X-Frame-Options header is not present.
+ /: The X-Content-Type-Options header is not set.
+ /robots.txt: contains 1 entry which should be manually viewed.
+ 8000 requests: 0 error(s) and 3 item(s) reported on remote host
À RETENIR

Les lignes débutant par + sont des constats à vérifier, pas des preuves.

RÈGLE R6 Toute alerte se vérifie (rappel)

Chaque ligne de Nikto est une hypothèse. Le tableau ci-dessous indique comment la vérifier.

ÉTAPE 4.2.3Vérifier chaque type d'alerte

Type d'alerteVérificationRemarque
En-tête de sécurité absentcurl -I http://192.168.56.20:3000/ puis lire les en-têtesVérifier s'il est réellement absent, et son utilité dans ce contexte
Entrée dans robots.txtcurl http://192.168.56.20:3000/robots.txtrobots.txt est public par nature ; il indique des chemins, pas des secrets
Version de logiciel divulguéeComparer la version aux avis de sécurité de l'éditeurUne version ancienne n'est pas automatiquement vulnérable
Listage de répertoireOuvrir l'URL dans le navigateurVérifier le contenu réel des fichiers
Référence à une faille connue (CVE)Lire l'avis, comparer version et configurationBeaucoup de références ne s'appliquent pas à votre cible
lecture des en-têtes (illustratif : la réponse réelle peut différer de l'alerte Nikto)
kali@kali:~$ curl -I http://192.168.56.20:3000/
HTTP/1.1 200 OK
Access-Control-Allow-Origin: *
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
Content-Type: text/html; charset=UTF-8

Dans cet exemple, un en-tête signalé « absent » par Nikto est en réalité présent : c'est la preuve qu'une alerte doit toujours être confrontée à une vérification manuelle.

Les en-têtes HTTP à connaître

En-têteRôle
Server, X-Powered-ByRévèlent le logiciel serveur (information technique)
Content-TypeType du contenu renvoyé
Set-CookieCréation d'un cookie ; vérifier les attributs Secure, HttpOnly, SameSite
X-Frame-OptionsLimite l'inclusion de la page dans une autre (clickjacking)
X-Content-Type-Optionsnosniff empêche le navigateur de deviner le type
Content-Security-PolicyRestreint les sources de scripts et de contenus
Strict-Transport-SecurityImpose HTTPS ; n'a de sens qu'en HTTPS
PIÈGE

Signaler l'absence de Strict-Transport-Security sur un service en HTTP est une consigne de bon sens, mais l'en-tête n'a aucun effet tant que le site n'est pas servi en HTTPS.

PIÈGE

Juice Shop est une application monopage. Certains tests de Nikto peuvent obtenir des réponses « 200 » génériques et signaler des fichiers qui n'existent pas. D'où la règle : toute alerte se vérifie.

4.3 Gobuster — découvrir des chemins web

DÉFINITION Énumération par dictionnaire

Technique qui teste, pour chaque mot d'une liste, si l'URL http://cible/mot existe, et note le code de réponse. Gobuster ne trouve que ce qui figure dans la liste.

ÉTAPE 4.3.1Créer une liste de mots

kali@kali: ~
kali@kali:~$ cat > ~/atelier-kali-1/paths.txt <<'EOF'
robots.txt
sitemap.xml
admin
backup
uploads
assets
ftp
EOF
kali@kali:~$ cat ~/atelier-kali-1/paths.txt

cat > fichier <<'EOF' écrit les lignes suivantes dans le fichier jusqu'à la ligne EOF. Les guillemets autour de EOF empêchent le shell d'interpréter le contenu.

ÉTAPE 4.3.2Lancer l'énumération

kali@kali: ~
kali@kali:~$ gobuster dir -u http://192.168.56.20:3000/ \
      -w ~/atelier-kali-1/paths.txt -t 10 \
      -o ~/atelier-kali-1/gobuster/dirs.txt

Le caractère \ en fin de ligne indique que la commande continue sur la ligne suivante.

ParamètreSignification
dirMode découverte de répertoires et fichiers
-uURL de base
-wListe de mots
-t 1010 tâches en parallèle (augmenter charge le serveur)
-oFichier de sortie
-x txt,bak (facultatif)Ajoute des extensions à chaque mot
-s / -b (facultatif)Codes de statut à retenir / à exclure

ÉTAPE 4.3.3Lire le résultat (illustratif)

résultat Gobuster (illustratif)

ÉTAPE 4.3.4Valider un résultat avec curl

kali@kali: ~
kali@kali:~$ curl -sS -o /dev/null -w '%{http_code} %{content_type} %{size_download}\n' \
      http://192.168.56.20:3000/robots.txt
200 text/plain; charset=UTF-8 28
kali@kali:~$ curl -sS -D - -o /dev/null http://192.168.56.20:3000/backup
OptionRôle
-sSilencieux (pas de barre de progression)
-SAffiche tout de même les erreurs
-o /dev/nullJette le corps de la réponse
-w '…'Affiche des variables après la requête (code, type, taille)
-D -Affiche les en-têtes de réponse
-IEnvoie une requête HEAD (en-têtes seuls)
-iInclut les en-têtes dans la sortie
-LSuit les redirections

ÉTAPE 4.3.5Repérer un faux positif

Si Gobuster signale presque tous les chemins avec la même taille, l'application renvoie probablement une page générique. Testez un chemin qui n'existe certainement pas :

kali@kali: ~ (cas d'un faux positif : 200 générique)
kali@kali:~$ curl -sS -o /dev/null -w '%{http_code} %{size_download}\n' \
      http://192.168.56.20:3000/zz-inexistant-4821
200 75002
  • Si la réponse est un 200 de même taille que celle des chemins « trouvés » : ces résultats sont des faux positifs.
  • Si c'est un 404 : les 200 ont plus de chances d'être réels, mais il faut encore en vérifier le contenu.
  • Les versions récentes de Gobuster signalent ce cas d'elles-mêmes et proposent d'exclure un code ou une taille (option --exclude-length selon la version ; consultez gobuster dir --help).
NE PAS CONCLURE

Qu'un chemin découvert contient des données sensibles. /assets est un dossier de ressources normales ; /ftp doit être ouvert et lu avant toute classification.

BONNE PRATIQUE

Une énumération génère des centaines ou milliers de requêtes. En situation réelle (avec autorisation), on la planifie avec le responsable du système, car elle est visible dans les journaux et peut charger le service.
