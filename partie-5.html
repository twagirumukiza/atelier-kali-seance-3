Partie 5 — Pratiquer : capture et métadonnées

OBJECTIF

Capturer un échange HTTP dans le laboratoire, le relire avec Wireshark et tshark, constater qu'il est lisible en clair, puis examiner les métadonnées d'un fichier avec ExifTool.

5.1 Wireshark en situation : capturer un échange HTTP

RÈGLE R15 Protéger les captures

Une capture (.pcapng) peut contenir des identifiants, des cookies, des données personnelles. Elle est stockée dans le dossier de travail du labo, jamais envoyée par messagerie ni publiée, et supprimée une fois l'exercice terminé.

ÉTAPE 5.1.1Identifier l'interface Host-only

kali@kali: ~
kali@kali:~$ ip -br addr
lo               UNKNOWN   127.0.0.1/8
eth0             DOWN
eth1             UP        192.168.56.10/24
kali@kali:~$ tshark -D
1. eth1
2. eth0
3. any
4. lo (Loopback)
PIÈGE

Capturer sur la mauvaise interface : aucun paquet attendu n'apparaît. Le trafic Kali ↔ cible passe par la carte Host-only (ici eth1), pas par lo.

ÉTAPE 5.1.2Démarrer la capture avec un filtre de capture

Dans Wireshark : Capture → Options, sélectionner eth1, champ « Filtre de capture » : host 192.168.56.20 and port 3000, puis Démarrer. L'équivalent en ligne de commande :

kali@kali: ~
kali@kali:~$ tshark -i eth1 -f "host 192.168.56.20 and port 3000" -a duration:30 \
      -w ~/atelier-kali-1/wireshark/httptest.pcapng
Capturing on 'eth1'
(laisser tourner : on génère du trafic dans un second terminal)
PIÈGE

Un filtre de capture erroné fait perdre définitivement des paquets (ils ne sont pas enregistrés). En cas de doute, capturez sans filtre et filtrez à l'affichage.

ÉTAPE 5.1.3Générer du trafic (second terminal)

kali@kali: ~ (second terminal)
kali@kali:~$ curl -i http://192.168.56.20:3000/robots.txt
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 28

User-agent: *
Disallow: /ftp
kali@kali:~$ curl -sS -X POST http://192.168.56.20:3000/rest/user/login \
      -H 'Content-Type: application/json' \
      -d '{"email":"demo@labo.test","password":"faux-mot-de-passe-1"}'
Invalid email or password.
RÈGLE R2 Données fictives (rappel)

Les identifiants ci-dessus sont inventés. On ne saisit jamais un vrai mot de passe dans un test de capture.

ÉTAPE 5.1.4Arrêter, enregistrer, relire

Arrêtez la capture (carré rouge) et enregistrez sous ~/atelier-kali-1/wireshark/httptest.pcapng. Relisez-la en ligne de commande :

résultat tshark (illustratif)
kali@kali:~$ tshark -r ~/atelier-kali-1/wireshark/httptest.pcapng -Y http
  4 0.000412 192.168.56.10 → 192.168.56.20 HTTP 143 GET /robots.txt HTTP/1.1
  6 0.003120 192.168.56.20 → 192.168.56.10 HTTP 391 HTTP/1.1 200 OK (text/plain)
 12 5.210874 192.168.56.10 → 192.168.56.20 HTTP 291 POST /rest/user/login HTTP/1.1 (application/json)
 14 5.226310 192.168.56.20 → 192.168.56.10 HTTP 322 HTTP/1.1 401 Unauthorized (text/html)

ÉTAPE 5.1.5Observer le début de la connexion TCP

filtre d'affichage Wireshark
tcp.flags.syn == 1

Vous devez voir, pour chaque connexion, [SYN] puis [SYN, ACK] puis [ACK] : la poignée de main en trois temps vue en partie 1.

ÉTAPE 5.1.6Suivre le flux TCP : constater le clair

Dans Wireshark : clic droit sur un paquet HTTP → Suivre → Flux TCP. Équivalent en ligne de commande :

flux TCP reconstitué (illustratif)
kali@kali:~$ tshark -r ~/atelier-kali-1/wireshark/httptest.pcapng -q -z follow,tcp,ascii,1
===================================================================
Follow: tcp,ascii
Node 0: 192.168.56.10:51234
Node 1: 192.168.56.20:3000
POST /rest/user/login HTTP/1.1
Host: 192.168.56.20:3000
Content-Type: application/json

{"email":"demo@labo.test","password":"faux-mot-de-passe-1"}
ATTENDU

L'adresse e-mail et le mot de passe (fictifs) apparaissent en clair dans la capture, parce que la connexion est en HTTP et non en HTTPS.

À RETENIR Ce que cela démontre

Toute personne capable d'observer ce segment réseau peut lire ce qui y transite en HTTP. C'est la raison d'être de la règle R3 (chiffrer les échanges).

NE PAS CONCLURE

Que Juice Shop est « piratable » : on a seulement constaté qu'un échange HTTP est lisible. L'authentification a d'ailleurs bien refusé ces identifiants fictifs.

5.2 ExifTool : les métadonnées

DÉFINITION Métadonnées

Données qui décrivent un fichier sans en faire partie visible : auteur, logiciel, appareil, date, parfois position GPS (EXIF dans les images). Elles voyagent avec le fichier, même si l'on ne les voit pas à l'écran.

ÉTAPE 5.2.1Récupérer un fichier du labo

kali@kali: ~
kali@kali:~$ curl -sS -o ~/atelier-kali-1/metadata/apple_juice.jpg \
      http://192.168.56.20:3000/assets/public/images/products/apple_juice.jpg
kali@kali:~$ file ~/atelier-kali-1/metadata/apple_juice.jpg
apple_juice.jpg: JPEG image data, JFIF standard 1.01, 1000x1000
PIÈGE

Le chemin de l'image dépend de la version de Juice Shop. Si le téléchargement échoue (404), repérez un nom d'image dans le navigateur (clic droit → copier l'adresse de l'image).

ÉTAPE 5.2.2Lire les métadonnées

résultat ExifTool (illustratif)
kali@kali:~$ exiftool ~/atelier-kali-1/metadata/apple_juice.jpg
ExifTool Version Number         : 12.xx
File Name                       : apple_juice.jpg
File Size                       : 71 kB
File Type                       : JPEG
MIME Type                       : image/jpeg
Image Width                     : 1000
Image Height                    : 1000

ÉTAPE 5.2.3Ajouter des métadonnées fictives pour la démonstration

kali@kali: ~
kali@kali:~$ exiftool -Artist="Etudiant Test" -Copyright="Labo BTS SIO" -Comment="demo atelier" \
      ~/atelier-kali-1/metadata/apple_juice.jpg
    1 image files updated
kali@kali:~$ exiftool -a -G1 -s ~/atelier-kali-1/metadata/apple_juice.jpg | grep -E "Artist|Copyright|Comment"
[IFD0]          Artist                          : Etudiant Test
[IFD0]          Copyright                       : Labo BTS SIO
[File]          Comment                         : demo atelier
OptionRôle
-aAffiche aussi les champs en double
-G1Indique le groupe de chaque champ (EXIF, IPTC, XMP…)
-sNoms de champs courts
-gps:allAffiche uniquement les champs de géolocalisation
-all=Efface toutes les métadonnées (crée une copie _original)
-overwrite_originalN'enregistre pas de copie de sauvegarde

ÉTAPE 5.2.4Cas réel : une photo de smartphone

Une photo prise avec un téléphone contient souvent la position, la date et le modèle de l'appareil :

exemple fictif — ne jamais utiliser la photo d'un tiers
kali@kali:~$ exiftool -gps:all -Make -Model -DateTimeOriginal photo_telephone.jpg
Make                            : ExampleCorp
Model                           : Phone X
Date/Time Original              : 2026:10:14 18:42:07
GPS Latitude                    : 48 deg 51' 24.00" N
GPS Longitude                   : 2 deg 21' 07.00" E
NE PAS CONCLURE

Qu'une position GPS lue dans une image est celle du lieu actuel de la personne : c'est le lieu de prise de vue, à la date indiquée, et la valeur peut être modifiée.

ÉTAPE 5.2.5Nettoyer avant de publier

kali@kali: ~
kali@kali:~$ exiftool -all= -overwrite_original ~/atelier-kali-1/metadata/apple_juice.jpg
    1 image files updated
kali@kali:~$ exiftool ~/atelier-kali-1/metadata/apple_juice.jpg | grep -E "Artist|GPS"
(aucune ligne : les métadonnées ont été supprimées)
RÈGLE R16 Nettoyer les métadonnées avant diffusion

Avant de publier une image ou un document, on supprime les métadonnées inutiles (position, auteur, logiciel, historique). Elles peuvent révéler un lieu, une identité ou un outil interne.
